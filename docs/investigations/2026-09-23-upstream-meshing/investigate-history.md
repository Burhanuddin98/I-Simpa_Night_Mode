# Upstream I-Simpa: history and issues lens

The scratch files are in `B:/repos/I-Simpa_Night_Mode/target/investigate/upstream-history/`. They include a blobless clone of upstream in `isimpa-blobless/` (1,067 commits), the issue and comment JSON, and the TetGen source from both tags. I made 37 web and git fetches.

## Findings

**1. TetGen went from 1.5 to 1.6 in PR #275 (wbinek), merged 2021-04-20. No release before v1.4.0 shipped 1.6.**
- The 1.6 commit is `ef2f7648ce4cf759c1d7d37ef3c6916530fde9e9`, dated 2021-04-20 13:01 +0200, titled "Update tetgen to 1.6". It changes `tetgen.cxx` (+14099/−8493 across 3 files). It sits alongside `68356ee` ("Add import of skipped_faces file during tetgen debug"). The merge is `06ab222` ("Merge pull request #275 … Tetgen update"). Source: `git log -- src/tetgen` in the clone.
- The other `src/tetgen` commits are older or build-only: `4db335c` 2016-08-11 "Build tetgen from sources", then CRT/NSIS/cmake housekeeping (2016–2018 and 2025–2026).
- TetGen version in `tetgen.h` line 7, by commit:
  - `4db335c`, v1.3.0, v1.3.3 and v1.3.4: "Version 1.5, November 4, 2013".
  - `68356ee`: "Version 1.6.0, August 31, 2020".
- Which tags contain `ef2f764` (`git merge-base --is-ancestor`): v1.3.4 **no**, v1.3.5_snapshot_2026_01_09 yes, v1.4.0_snapshot_14_01_2026 yes.
- The fix landed on the `dev` branch. nicolas-f on PR #275, 2021-04-20T12:08Z: "I've switched to ifsttar:dev … and set last release on ifsttar/master". The main line kept 1.5 until `d32e88d`, dated 2024-09-26 09:33 +0200 ("Merge pull request #386 … linux_release"). Its main-side parent `83e6ed9` (2024-01-18) still reads "Version 1.5"; its other parent `21435ef` reads "Version 1.6.0".
- Our checkout's `tetgen.cxx` matches the git blob at 929a5c8 byte for byte once CR is stripped (`cmp`).

**2. The author of the upgrade reported, 3 days later, that TetGen 1.6 ignores the area constraint. The upgrade was never reverted.**
- wbinek (CONTRIBUTOR) on PR #275, 2021-04-23T13:54:10Z (https://github.com/Universite-Gustave-Eiffel/I-Simpa/pull/275#issuecomment-825675074), quoted: "I have noticed that Tetgen 1.6 does not respect the face area constrain properly. This leads to problems making maps on model surfaces. I have wrote to Tetgen authors … As for now I would recommend reverting this update and leaving it as PR waiting for some fix."
- There were no replies after it: the thread has 4 comments and this is the last.
- `git log --all -i --grep=revert` finds only 2017 reverts, and none touch tetgen. v1.4.0 ships TetGen 1.6.
- The source confirms it:
  - **TetGen 1.5 at v1.3.4** enforces the constraint. In `tetgen_v1.3.4.cxx:24580-24584`, `checkfac4split` contains `if (checkconstraints && (areabound(*chkfac) > 0.0)) { if (area > areabound(*chkfac)) { qflag = 1; return 1; } }`.
  - **TetGen 1.6.0 at v1.4.0** never reads `areabound(`. The only reads are commented out, at lines 12361, 12606 and 12726. `check_subface` (27347-27388) tests only `radius/emin > b->minratio`.
  - Both versions still load the `.var` file unconditionally when opening a `.poly` (1.5: 2385; 1.6: 2449) and set `checkconstraints = 1` (1.5: 4569; 1.6: 4860). So 1.6 reads the `.var` and then never uses it.
- This is an independent upstream receipt for our measured "tutorial box → 6 tets with or without .var".

**3. Upstream's 2019 tutorial-1 mesh was generated by TetGen 1.5, using the command stored in the project.**
- In `tutorial_1.proj`, the files `instance2/temp/scene_mesh.1.{node,ele,face,edge,neigh}` are zip-dated 2019-06-07 11:58:42. Every one ends with: `# Generated by meshing\tetgen\tetgen.exe -pq2 -A -n D:\picaut\AppData\Roaming\isimpa\current\instance1\temp\scene_mesh.poly`
- Their headers read `2257 4 1` (.ele), `732 3 0 0` (.node) and `1270 1` (.face). These counts match the fixture.
- The tutorial was committed by Picaut in `3deb1ff` on 2019-06-07 ("Update documentation"). At that date the source tree held TetGen 1.5, since 1.6 arrived in 2021. That the binary Picaut ran was 1.5 is [inferred].
- The SPPS meshing block of the project's `projet_config.xml` (lines 2480-2488) is: minratio=2, appendparams="", isareaconstraint=1, constraintrecepteurss=0.1, ismaxvol=0, preprocess=1. The `.var` asks for facet marker 0 and 1 → 0.100000001490116. The resulting floor faces are ≤0.0998 m², which is what TetGen 1.5 area enforcement produces [inferred from the code above].

**4. The defaults changed after the tutorial mesh was made.**
- Commit `bda1bb0`, 2019-06-24, nicolas-f: "limit the number of tetrahedron for reducing the computation time and propagation issues". It changed the minratio default from 2 to 5 and the appendparams default from "" to "-Y". Ticking isareaconstraint sets appendparams to "" and unticking sets it back to "-Y" (`e_core_core_tetconf.h`).
- v1.3.4 contains `bda1bb0`. So v1.3.4 already defaulted to `-pq5 -A -n -Y` with TetGen 1.5, and the tutorial's saved `-pq2` settings predate that change.
- Neither `projet_maillage.cpp` nor `e_core_core_tetconf.h` changed how TetGen is called after 2019, apart from the skipped-faces debug import (`68356ee`) and 2025 header and path edits.

**5. Release notes**
- v1.3.4, published 2020-12-23T17:22:45Z. Assets: `isimpa-1.3.4-win64.exe` (68,462,026 B) and `.zip` (104,059,742 B). The notes (158 chars) are about Python 3.8, offline docs, import units and FreeCad import, and end "patch note will be updated later". They say nothing about TetGen or meshing. Source: the `releases.json` saved by the release-binary lens.
- **v1.4.0**, "Preview 1.4.0", pre-release, dated 09 Jan (fetched https://github.com/Universite-Gustave-Eiffel/I-Simpa/releases/tag/v1.4.0_snapshot_14_01_2026). The notes have exactly one meshing line: "Tetgen update by @wbinek in #275". They do not mention the area-constraint regression. The "Full Changelog" link is `v1.3.4...v1.3.5_snapshot_2026_01_09`.
- No release exists between v1.3.4 and v1.4.0 (7 release objects). So every pre-2026 release ships TetGen 1.5 [inferred from tag contents], and v1.4.0 is the first to ship 1.6.
- There is no TetGen release after 1.6.0 (fetched https://wias-berlin.de/software/tetgen/relnotes.html: "Version 1.6.0 (August 31, 2020)" is the latest). That page does not mention area constraints.

**6. Issues and discussions**

The API returned 338 issues and PRs, numbers up to 428, of which 110 are PRs. I grepped their titles and bodies and ran GitHub search over comments for "tetgen" (13 hits), "constraint" (1) and "maillage" (1).
- **Area constraint:** the only hits are PR #275 (above) and #125 (2017, a translation of "Surface receivers constraint (m²)"). No user issue reports coarse or flat surface-receiver maps caused by meshing.
- **Mesh refinement:** Discussion #356 "Mesh Quality", 2023-03-24, maintainer nicolas-f:
  - "mesh has no impact on computation results on spps as it is only used as an index structure"
  - "By default you have the tetgen option -Y provided. It remove the adding of points on the boundary, you can remove this option."
  - "To have smaller tetrahedron you have to reduce the value of volume constraint"
  - These are paraphrased by the fetcher around quoted fragments; the exact wording needs a check.
- **Surface receivers black or flat:**
  - #420 (2026-01-26): a black colormap on the Flatpak/Linux build. nicolas-f replied on 2026-01-26: "surface receivers does not work on Linux and Mac release … file driver and the open gl instructions".
  - #425 and PR #426 (2026-07-06): the root cause is an LP64 `memcpy(sizeof(ivec3))` into an `int32_t[3]`, so Windows is unaffected. These are not mesh-related.
- **Source position and crashes:**
  - #215 (2018-05-17, MEMBER nicolas-f, still open, 0 comments): "SPPS crash when sound sources are outside of 3D models".
  - #37 was closed via `8113ce1` on 2017-04-20. That commit added the `CheckSourcePosition` error "A sound source position is intersecting with the 3D model" (`src/spps/sppsNantes.cpp:323`).
  - "Unable to find the source position!" appears only in code (`sppsNantes.cpp:63`, a return when `currentVolume` is NULL). No issue quotes it.
  - No issue mentions 0xC0000005 or an access violation at SPPS start.
- **Broken mesh passes silently:** #348 (2022-12-09) and #421 (2026-03-03) show TetGen reporting "A self-intersection was detected. Program stopped." The GUI then logs "Meshing complete", and SPPS reports "Tetrahedron file is empty". nicolas-f's answer on #421 (2026-03-04) was that the user must fix the model.
- **Tutorial 1 in v1.3.4:** #381 (2024-04-20), the reporter ran tutorial1 in "I-SIMPA v. 1.3.4 built on 2020-12-23". nicolas-f said the screenshot was the TetGen mesh preview. Nothing in the thread is about mesh density.
