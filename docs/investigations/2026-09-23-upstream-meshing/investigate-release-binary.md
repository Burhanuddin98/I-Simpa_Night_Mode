# What upstream actually ships: TetGen and SPPS binaries, 1.3.3, 1.3.4 and 1.4.0 (release-binary lens)

Scratch folder: `B:/repos/I-Simpa_Night_Mode/target/investigate/release-binary/` (called RB below). B: had 43.06 GB free before I started. The downloaded and extracted files take 4.6 GB. Nothing was deleted and no installer was run.

**Answer:** The shipped 1.4.0 TetGen does not honour the `.var`. The shipped 1.3.4 TetGen does, as long as `-Y` is off. Upstream's 2019 tutorial mesh was made with TetGen 1.5 (shipped in 1.3.3 and 1.3.4) using `-pq2 -A -n`. Rerunning 1.3.3 and 1.3.4 on the fixture inputs reproduces it: every output file matches except the "Generated by" footer line. The shipped 1.4.0 TetGen matches our build's output exactly.

- All runs exited with rc=0, and every log says "Opening scene_mesh.var" when the `.var` was present.
- So the shipped 1.4.0 TetGen does not honour the `.var`, and the shipped 1.3.4 TetGen does when `-Y` is absent.
- Shipped 1.4.0 and our 1.6 build give identical output files (excluding the "Generated by" footer) in all 7 arms both were run on.

**F4. 1.6 refinement is also inert for radius-edge quality on this box, not only for area** [the mechanism is inferred; this lens has behaviour only]
- In the 1.4.0 `q2-var` log, lines like "10 insertions, added 0 points, 4 tetrahedra in queue" appear through to the end.
- Those refine lines are identical with and without the `.var`, so the `.var` never enters the queue.
- At `-pq1.414`, the 6 box tets must break the bound: circumradius is half the box diagonal, 6.02, and the shortest edge is 3, giving a ratio of about 2.0 [inferred]. 1.6 still inserts 0 points; 1.5 makes 134 tets.
- A volume constraint does refine in 1.6 (`-pa1` gives 344 tets).
- So "check_subface tests only radius-edge" does not explain everything: radius-edge refinement also adds nothing here.

**F5. The 2019 tutorial mesh came from TetGen 1.5 with `-pq2 -A -n`**
- The .proj archive (`tutorial 1/tutorial_1.proj`, 7z listing) contains `instance2/temp/scene_mesh.1.{node,ele,face,edge,neigh}`, dated 2019-06-07 11:58:42.
- Their footer reads: `# Generated by meshing\tetgen\tetgen.exe -pq2 -A -n D:\picaut\AppData\Roaming\isimpa\current\instance1\temp\scene_mesh.poly`
- `diff` of the 1.3.4 rerun (`runs/v134/q2-var`) against those files: the only differing line in each of the 5 files is that footer.
- 1.3.3's TetGen gives the same body in all 5 files.
- Against the fixture `spps/tetramesh.mbin` (`RB/cmp_mbin.py`; size 234,492 = 8 + 732·12 + 2257·100):
  - node order is identical, max coordinate difference 4.77e-7 (float32 rounding);
  - all 2257 tet rows match as vertex sets, row for row;
  - the vertex order within a row differs in every row, so the GUI's converter reorders vertices [inferred].
- `-Y` was not used, and neither was `-a`.

**F6. The default GUI settings give 6 tets in both releases.**
- At tag v1.3.4 (raw `e_core_core_tetconf.h`, HTTP 200): `minratio` 5 (line 103), `appendparams` "-Y" (line 106), `isareaconstraint` false (line 109). This matches 1.4.0 at `tree_core/e_core_core_tetconf.h:82-109`.
- v1.3.4 `projet_maillage.cpp:173-175` builds the same command line, and writes the `.var` only when `isAreaConstraint` is on (line 221).
- With defaults the command is `-pq5 -A -n -Y` with no `.var`, which gives 6 tets on both 1.3.4 and 1.4.0.
- With "Surface receivers constraint" on, 1.3.4 refines (1362 tets, 934 floor faces) and 1.4.0 stays at 6.

**F7. Preprocess has no effect here.** The shipped `preprocess.exe` from 1.3.4 and from 1.4.0 leaves the tutorial `.poly` byte-identical (`cmp`). Its log says "Vertices merged : 0 / Coplanar Faces destroyed : 0". TetGen results after it are unchanged: 2257 tets on 1.3.4, 6 on 1.4.0.

**F8. The 2019 project's saved settings don't match what produced its mesh.**
- `instance2/projet_config.xml` (archive date 2019-06-11) has `minratio`=2, `appendparams`="", `isareaconstraint`=0, `constraintrecepteurss`=5, `ismaxvol`=1 with `maxvol` 0.1, `preprocess`=1.
- The 06-07 run, however, has no `-a` on its command line, and its `.var` holds 0.1 m² on markers 0 and 1, not 5.
- Either the settings were changed after meshing, or the 2019 build assembled the command differently [inferred].
